# p-02 — Re-Ray 試作構成(T-Beam + XIAO ESP32S3 + GUIDE01)

## 目的

企画書「Re-Ray」の中核を、手持ちの部品で実機検証する。

- **LoRaの端末間リレーで、回線(Wi-Fi/携帯)が落ちていても、定型信号とSOSが届き、本部からの指示も現場に届くか**
- **届いたか届いていないかが、送った本人に分かるか**(受領確認)
- **受け取った内容を、ARグラス(GUIDE01)に表示できるか**(公式アプリなし)
- 企画書の目標値(**LoRa 約600m / 端末間リレーで2km規模**)を、**実測で確かめる**

これは「できる/できない」を事実で判定するための試作であり、製品コードではない。
(p-01 は M5Stick-C 前提だったため、p-02 が置き換える。GUIDE01 の接続確認は p-02 の S1 に含む。)

## 構成

```
                         ┌──────────── 端末セット(1人分) ────────────┐
  [GUIDE01]  <--BLE-->  [XIAO ESP32S3]  <--UART-->  [T-Beam]  <--LoRa 920MHz-->  (他のT-Beam: 端末/中継)
  (表示)                  (表示・入力の橋渡し)         (LoRa・GPS・電池・ボタン)              |
                                                                                        | LoRa
                                                                              [T-Beam: 出口ノード]
                                                                                        | Wi-Fi/MQTT
                                                                                    [PC: サーバー]
                                                                         (Mosquitto + 検証用ビューア/指示送信)
```

役割分担の理由:T-Beam は ESP32(LX6)で、LoRa・GPS・Wi-Fi・BLE を1枚で持つが、
**BLE + Wi-Fi + LoRa を同時に動かすと不安定になる可能性**がある。
そこで試作では、**LoRaとGPS・電池を T-Beam、GUIDE01 との BLE を XIAO ESP32S3** に分け、UART でつなぐ(フェーズA)。
安定性が確認できたら、BLE を T-Beam に統合する(フェーズB、任意)。

## ノードの種類(ファームは共通。設定で役割を切り替える)

| 役割 | 機材 | 内容 |
|---|---|---|
| 端末(TERMINAL) | T-Beam + XIAO + GUIDE01 | ボタンで定型報告、受信した指示・送達状態をグラスに表示。中継も兼ねる |
| 中継(RELAY) | T-Beam 単体 | 受信 → 重複排除 → 再送 |
| 出口(GATEWAY) | T-Beam(Wi-Fi 接続) | LoRa ⇄ MQTT の橋渡し。サーバー到達の受領確認(ACK)を返す |
| サーバー | PC | Mosquitto、検証用ビューア、指示の送信、ログ |

## 材料

`docs/BOM.md` を参照。要点:

- LILYGO T-Beam(920MHz MIC / Non-Soldered OLED)× 3 以上 ※発注済みか要確認
- 18650 リチウム電池(保護回路付き)× 3
- Seeed XIAO ESP32S3 × 1(手持ち)
- GUIDE01 × 1 ※手元にあるか要確認
- PC(PlatformIO、Mosquitto)

## 進め方

詳細は `docs/TEST_PLAN.md`。

| 段階 | 内容 |
|---|---|
| S0 | 環境・技適・規制の確認(**ここが終わるまで LoRa の電波を出さない**) |
| S1 | GUIDE01 × XIAO ESP32S3:接続・文字表示・タッチ取得(公式アプリなし) |
| S2 | T-Beam 2台:LoRa 送受信、GPS、電池管理、ボタン |
| S3 | フレーム仕様の実装:署名、重複排除、受領確認 |
| S4 | T-Beam 3台:リレー(A → B → C)の動作と到達率 |
| S5 | 出口ノード:LoRa ⇄ MQTT ⇄ PC、上り(報告)と下り(指示)、ログ |
| S6 | 結合:T-Beam ⇄ XIAO ⇄ GUIDE01 で、報告の入力と指示の表示 |
| S7 | 屋外の到達実測(距離、見通し、人の多い環境、アンテナ高さ・持ち方) |
| S8 | 電池持ちの実測 |

## 企画書の主張と、確かめるテスト

| 企画書の主張 | 確かめるテスト |
|---|---|
| LoRaで約600m届く(目標値) | S7 |
| 端末間リレーで2km規模でも端から端まで届く(目標値) | S4, S7 |
| 回線が落ちていても指示が届く | S5 |
| 受領確認で「届いたか」が分かる | S3, S5, S6 |
| ARグラスに文字で表示、両手が空く | S1, S6 |
| ログが残り、後から見返せる | S5 |
| 位置は端末番号と区域の対応表から割り出す | S5(サーバー側の対応表) |
| 電池で長く待機できる | S8 |

## 未確認・要確認(開始前)

1. 発注済みの T-Beam が、**AXP2101 搭載の V1.2** か(MIC 証明書の対象)
2. T-Beam の**技適に関する表示**(基板・梱包)と、証明書の条件を守れる設定にできるか
3. **XIAO ESP32S3 の技適**(Wi-Fi/BLE の電波を出す前に確認)
4. GUIDE01 本体が手元にあるか
5. T-Beam の台数(最小3台。2台なら S4 のリレー試験ができない)
6. 使用するチャンネル・送信時間の規定(ARIB STD-T108)の確認結果

詳しくは `docs/COMPLIANCE.md`。
