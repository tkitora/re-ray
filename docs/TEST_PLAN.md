## S4:3台でのリレー(A → B → C)

A と C が直接届かない配置(距離または遮蔽物)を作る。

- [ ] 重複排除つきフラッディングの動作(ttl、バックオフ、抑制)
- [ ] 100回の REPORT で、到達率、ホップ数、遅延、重複再送の回数を測る
- [ ] パラメータ(SF、ttl、バックオフ範囲、抑制の閾値 k)を振って比較
- [ ] 送信時間の予算管理が働く(上限に近づくと優先度の低いフレームを送らない)
- 合格(案):A → C の到達率 90% 以上(100回、試験環境で)。数字は目安で、結果を見て相談

## S5:出口ノードとサーバー

- [ ] T-Beam(出口)を Wi-Fi につなぎ、Mosquitto に接続
- [ ] 上り:LoRa で受けた REPORT / SOS が、MQTT で PC に届き、ログに残る
- [ ] サーバー到達の ACK が、LoRa で端末に戻る
- [ ] 下り:PC から指示を MQTT で出し、出口が LoRa で放送、端末が受信
- [ ] 「指示受領」の ACK が PC に集まり、受領した端末と未受領の端末が分かる
- [ ] **回線断の模擬**:出口の Wi-Fi を切り、LoRa 側(層2・層3)が動き続けること、復旧後にキューが送られること
- [ ] 区域の対応表(端末番号 → 区域)で、PC のビューアに区域別の最新状況を出す
- 合格(案):上り・下りが10回ずつ成功し、回線断→復旧でキューが送られる

## S7:屋外の到達実測(**規制の確認が完了していること**)
