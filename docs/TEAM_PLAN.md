# 00 Re-Ray の進め方と目標(チーム全体)

作成: 2026-10-20 / 書いた人: ハード担当 / 状態: たたき台(チームで直してよい)

この文書は、**Re-Ray を 6 人でどう作っていくか**をまとめたものです。
技術の知識がなくても読めるように、言葉の説明から書いています。
企画プレゼン(2026-10-20 版)で約束したことを、どの順番で、誰が、いつまでに、どこまで作るかを決めます。

---

## 1. Re-Ray とは

**自治体の職員が、ふだんの連絡にも、災害のときにも、同じ道具で使える連絡システム**です。

職員は、メガネに付ける小さな画面(ARグラス)と、ポケットに入る小さな機械(端末)を持ちます。
本部の人は、パソコンの画面(管理画面)で、全員の状況を見たり、指示を送ったりします。

```
 現場の職員(1人ぶんのセット)                            本部
 ┌──────────────────────────────┐                    ┌──────────┐
 │ ARグラス ── 端末(マイコン)   │ ── 無線 ──▶ サーバー ──▶ │ 管理画面 │
 │ (文字が見える)  (ボタンで送る)│ ◀── 無線 ── (記録する) ◀── │ (PC)     │
 └──────────────────────────────┘                    └──────────┘
```

**ふだん**: 本部や仲間が話した内容が文字になり、ARグラスに出ます。両手がふさがっていても読めます。
**災害のとき**: 端末のボタンを押すと「無事です」「助けて」などの決まった信号が本部に届きます。本部からは「北口に集合」などの指示が届きます。
**携帯の電波が止まったとき**: 端末どうしが無線(LoRa)で信号をバケツリレーのように渡して、電波の届く場所まで運びます。

## 2. この文書で使う言葉

| 言葉 | 意味 |
|---|---|
| **端末** | 職員が持つ小さな機械。中身はマイコン(小さなコンピュータ)。画面はなく、ボタンと無線がある。今回の試作では **T-Beam** という基板と **XIAO** という基板の 2 枚を組み合わせて 1 台の端末にする |
| **ARグラス** | メガネに付ける表示装置。製品名は **GUIDE01**。端末から文字を受け取って目の前に映す |
| **サーバー** | 本部側のコンピュータ(のプログラム)。端末から届いたものを全部記録し、管理画面に渡し、管理画面からの指示を端末に送る |
| **管理画面** | 本部の人がブラウザで見る画面。端末の一覧、指示の送信、記録の閲覧ができる(「Web」とも呼ぶ) |
| **Wi-Fi** | ふだん使う無線。インターネットにつながる。これが生きていれば、端末はサーバーと直接やり取りできる |
| **LoRa(ローラ)** | 遠くまで届くが、少しの文字しか送れない無線。携帯もWi-Fiも使えないときの頼みの綱。1 区間 約 600m と見込んでいる(まだ測っていない) |
| **バケツリレー(中継)** | 端末 A の信号を端末 B が受け取って、さらに端末 C へ送ること。LoRa でこれをやると、台数を足すほど遠くへ届く |
| **出口** | LoRa で運ばれてきた信号を、Wi-Fi などを使ってサーバーへ送り出す端末。企画では SIM(携帯回線)付きの端末が出口だが、**今期は Wi-Fi(スマホのテザリング)で代わりにする** |
| **定型信号** | ボタンで送る、決まった意味の短い信号。「1 = SOS」「2 = 無事」「3 = 助けて」「4 = 食料」のように番号で決める。現場 → 本部 |
| **指示コード** | 本部から現場へ送る、決まった意味の短い指示。「移動」「集合」「退避」などを番号で決める。本部 → 現場 |
| **ポジション** | 「北口」「体育館前」のような、現場の場所に付けた番号。本部の画面で、番号に名前と場所をあとから付けたり変えたりできる。指示や定型信号に「どこへ」「今どこ」として添える |
| **文字起こし** | 話した声を文字に変えること。今回はスマホかパソコンのアプリで行い、できた文字をサーバーに送ってARグラスに出す |
| **技適(ぎてき)** | 無線機を日本で使ってよいという国の認証。T-Beam は認証を受けているが、**自分たちで作ったプログラムで動かしてよいかは確認が必要**(§6) |

## 3. 今期つくる範囲(2026-10-20 に決めたこと)

| やること | 作る / 作らない | 補足 |
|---|---|---|
| ボタンで定型信号を本部に送る | **作る** | 定型信号の種類は 4 つに限らず、必要なぶん用意する(最大 31) |
| 本部から現場へ指示を送る | **作る** | 自由な文章は Wi-Fi があるときだけ。LoRa では「指示コード + ポジション番号」の短い形で送る |
| ポジション(場所の番号)を本部で決めて使う | **作る** | 番号は端末に、名前は本部の画面に。回線が切れている間は端末には番号だけが届く |
| ARグラスに文字を出す | **作る** | 端末(XIAO)から ARグラスへ無線で送る |
| 話した声を文字にしてARグラスに出す(ふだんの使い方) | **作る** | スマホ/PC のアプリで文字にして、サーバー経由で配る。端末に声の処理は入れない |
| LoRa でバケツリレー | **作る(ただし後回し)** | T-Beam がまだ届いていない。先に Wi-Fi で全部つなぎ、LoRa はあとから足す |
| 管理画面(一覧・指示・記録) | **作る** | |
| 記録(ログ)を残して後から見る | **作る** | |
| SIM 付きの出口 | **作らない** | 今期は Wi-Fi で代わりにする。発表でもそう言う |
| イベント用・工事用のモジュール | **作らない** | 展望として話すだけ |

## 4. チームの分け方(6 人)

名前はまだ入れていません。各自で埋めてください。

| 役 | 人数 | やること | できあがりの形 | 担当者 |
|---|---|---|---|---|
| **端末 A(T-Beam)** | 1 | 端末の無線(Wi-Fi、LoRa)、位置(GPS)、電池、ボタンのプログラム。出口の役もここ。技適の確認もここ | ボタンを押すと信号がサーバーに届く。指示を受け取って ARグラス側に渡す | |
| **端末 B(XIAO と ARグラス)** | 1 | ARグラスとつないで文字を出すプログラム。T-Beam とのやり取り | ARグラスに文字が出る。タッチ操作が取れる | |
| **サーバー** | 1 | 端末から届いたものを記録し、管理画面に渡し、指示を端末に送るプログラム。ポジション表と指示コードもここで持つ | 疑似の端末 100 台ぶんのデータを欠けなく記録できる | |
| **管理画面(Web)** | 1 | 本部の画面。端末の一覧、指示の送信、記録の閲覧、ポジション表の編集 | 画面から指示を送り、「何台に届いたか」と記録が見える | |
| **文字起こしアプリ** | 1(Web かサーバーと兼任可) | スマホ/PC で声を文字にして、サーバーに送る小さなアプリ | 話した 1 文がサーバーの記録に文字で残る | **未着手。担当なし** |
| **とりまとめ** | 1(兼任) | パート間の約束ごと(信号の番号、データの形)を 1 か所に揃える。結合テストの進行。発表資料とデモの台本。実測の記録 | 約束ごとの文書に「案」が残っていない。発表の台本がある | |

## 5. 進め方(段階 0 〜 5)

ひとつの段階が終わるたびに、「できたと言える条件」を満たしたかを全員で確認します。
月は仮です。発表日が分かったら引き直します。

### 段階 0:約束ごとを決める・無線の許可を確かめる(10/20 〜 10 月末)

まだ「案」のままになっている約束ごとを決めきります。ここが決まらないと、各パートが別々の前提で作ってしまいます。

| すること | 担当 | できたと言える条件 |
|---|---|---|
| 定型信号の一覧、指示コードの一覧、ポジション番号の決まり、サーバーと端末の間のデータの形を、共通仕様の文書に書く | とりまとめ + 各パート | 共通仕様に「案」が残っていない |
| 技適を受けた T-Beam を、自分たちのプログラムで動かしてよいかを、総務省の総合通信局か認証機関に問い合わせる | 端末 A | 回答が文書に残っている。ダメなら段階 3 を代替案(§6)に切り替える |
| 文字起こしのやり方を決める(ブラウザの音声認識か、スマホの機能か) | 文字起こし | 1 文を文字にしてサーバーに送る試作が動く |
| 授業の提出物(システム構成図)を 1 枚にまとめる | とりまとめ | プレゼン 10 枚目の図と、共通仕様の内容が一致している |
| 管理画面の全画面を紙芝居(手描きでよい)にする | Web | 画面ごとに「サーバーのどの機能を使うか」が書いてある |

### 段階 1:パートごとに、実機なし・無線なしで動くところまで(11 月上旬)

T-Beam が届かなくても、電波を出さなくても、ここまでは進められます。

| パート | すること | できたと言える条件 |
|---|---|---|
| サーバー | 疑似の端末(プログラムで作った偽の端末)からの信号を記録する。指示を送る。ポジション表と指示コードの機能 | 疑似 100 件が欠け・重複なく記録される。壊れたデータを送っても止まらない |
| Web | 偽のサーバー相手に、全画面を作る | 画面から文字と指示を送り、「何台中何台に届いた」と記録が見える |
| 文字起こし | 声 → 文字 → サーバー | 話した 1 文が、サーバーの記録に文字で残る |
| 端末 B | ARグラスに文字を出す。タッチを取る | 日本語が 1 行に何文字・何行出せるかを実測した。100 回更新しても表示が崩れない |
| 端末 A | T-Beam が届いたら、**電波を出さない部分**(GPS、電池、ボタン、XIAO とのやり取り)と、**Wi-Fi でサーバーにつなぐ部分** | T-Beam が Wi-Fi 経由で、本物のサーバーに信号を送れる |

**この段階の全体の目標:** LoRa を使わずに、Wi-Fi だけで
「ボタン → サーバー → 管理画面」と「管理画面/文字起こし → サーバー → ARグラス」の 2 本が通ること。
LoRa が最悪使えなくても、ここまでできていれば発表のデモは成り立ちます。

### 段階 2:全部つなぐ(1 回目。室内、LoRa なし)(11 月中旬)

全員で 1 日取って、パートごとに作ったものを 1 本につなぎます。

- 職員 1 人ぶんのセット(T-Beam + XIAO + ARグラス。Wi-Fi でサーバーへ)と、サーバー、管理画面、文字起こしをつなぐ
- **できたと言える条件:** 端末のボタンで送った定型信号(ポジション付き)が管理画面の一覧に出る。管理画面の指示と、文字起こしの文が ARグラスに出る。記録が残る。これを 10 回ずつ
- ここで、§7 の判定表のうち LoRa に関係しない行を仮に埋める

### 段階 3:LoRa を足す(段階 0 の許可が取れて、T-Beam が揃ってから)(11 月下旬 〜 12 月上旬)

| すること | できたと言える条件 |
|---|---|
| T-Beam 2 台で LoRa の送受信。届いたことの返事(確認)を返す | 2 台で 10 回連続して届く |
| 3 台でバケツリレー(A → B → C。A と C は直接届かない配置) | A から C へ 10 回中 9 回以上届く |
| 出口の端末:LoRa で受けた信号をサーバーへ送る。本部の指示を LoRa で現場へ送る | 出口の Wi-Fi を切っても現場側は動き続け、戻したら溜まっていた分が届く。指示が LoRa 経由で ARグラスに出る |
| ARグラスの表示が「送った → 近くに届いた → 本部に届いた」と進む | 10 回中 10 回、表示が正しく進む |

### 段階 4:屋外で測る・判定する(12 月中旬)

- 見通しのよい場所で、100m ずつ離れて 600m まで、信号が届くかを測る。街なか、人の多い場所でも測る。持ち方・高さ・設定を揃えて記録する
- 電池で何時間動くかを測る
- **できたと言える条件:** §7 の判定表が全部埋まっている。600m に届かなくても、数字が出れば成果

### 段階 5:発表の準備(発表日の 2 週間前から)

- デモの台本を作る。いちばん効くのは、プレゼン 5 枚目の「電波が止まった」を目の前で再現すること:
  出口の Wi-Fi を切る → 現場のボタンを押す → LoRa 経由で管理画面に出る → 本部から指示 → ARグラスに出る
- プレゼンの「約 600m は想定値」を、実測した数字に差し替える
- 作らなかったもの(SIM、モジュール)は展望として話す

## 6. うまくいかないかもしれないこと

| 心配なこと | どうするか |
|---|---|
| 技適を受けた T-Beam を自分たちのプログラムで動かすのが、法律上ダメと言われる | 段階 0 で問い合わせる。ダメなら、LoRa の電波は出さず、パソコン上の模擬で仕組みを示し、実機のデモは Wi-Fi だけで行う。発表では「LoRa は設計と机上の検証まで」と正直に言う |
| 文字起こしの担当者がいない | §4 で 1 人置く。やり方は段階 0 で決める |
| ARグラスが 1 台しかない | ARグラスは 1 人だけ付け、バケツリレーは T-Beam 3 台で見せる |
| T-Beam の到着が遅れる | 遅れるのは段階 1 の端末 A の作業だけ。他は進む |
| 回線が切れている間に、本部がポジションの名前を変えても現場に届かない | 現場の ARグラスには番号で出す(「ポジション 3 へ移動」)。名前は Wi-Fi がつながったときに受け取る |

## 7. 全部できたら何が言えるか(判定表)

プレゼンで約束したことごとに、「できた / できない / 一部 / 未確認」を書きます。段階 2 と段階 4 で埋めます。

| プレゼンで約束したこと | 確かめる段階 | 結果 |
|---|---|---|
| 話した内容が文字になって ARグラスに出る(ふだん) | 2 | |
| ARグラスに文字で表示され、両手が空く | 1、2 | |
| 定型信号・SOS が本部に届く | 2(Wi-Fi)、3(LoRa) | |
| 本部からの指示が現場に届く(回線が切れていても) | 2(Wi-Fi)、3(LoRa) | |
| 届いたかどうかが分かる | 2、3 | |
| 管理画面で、端末ごとの場所(ポジション)と状況が一覧できる | 2 | |
| 記録が残り、後から見返せる | 2 | |
| LoRa で約 600m 届き、バケツリレーで延びる | 4 | |
| 電池で長く待機できる | 4 | |

## 8. チームの決まり

- **週に 1 回、「つなぐ時間」を決めておく。** パートが 3 つに分かれているので、つなぐ日を決めないと、最後まで一度もつながらないまま終わる
- パートをまたぐ約束ごと(信号の番号、データの形、名前)は、**先に共通仕様の文書に書いてから**プログラムに使う。変えたいときは、自分のパートの文書に「修正案」と書き、合意してから共通仕様を直す
- 測った数字は、やり方・回数・条件(場所、時刻、持ち方)を一緒に書く。**1 回だけ測った数字は「参考値」と書く**
- 文書と図は Google Drive、プログラムは GitHub に置く(端末のプログラム: `tkitora/re-ray`。サーバーと管理画面の置き場所は決まったらここに書く)
